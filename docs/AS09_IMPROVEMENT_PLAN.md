## 우선순위별 통제 실험

모든 ID는 내부 계획용이며 제출 파일 번호를 부여하지 않는다. 각 단계는 같은 기준선과 먼저 단독 비교하고, 이득이 확인된 단계만 결합한다.

### 1. KO-FUSION-01 — 한글 후보 선택 점수 학습

구현 명세: [SPEC-KO-FUSION-01 v1.0](SPEC_KO_FUSION_01.md). 문서 작성 완료이며 구현·학습·성능 검증은 planned다.

- **고정**: AS-09 인코더 구조·검색 설정·후보 ID 집합·조회 정책. 검증에서는 해당 분할에 맞게 학습된 자산을 사용한다.
- **변경**: 한글 후보 점수 결합만 작은 LightGBM 랭커로 학습한다. 기존 기본 점수, 문자/음운/자모 유사도, 숫자 일치, GT/IGT 각각의 오차와 결측, 국적·선종 호환, Dense 유사도·순위·점수차·Top-35 포함 여부를 입력한다. 첫 실험은 현재 점수 산출에 쓰인 특징으로 제한한다.
- **구성**: 입출항 기록 한 행의 후보들이 하나의 ranking query다. 정답 ID는 relevance 1, 나머지는 0으로 둔다. train/validation 분리는 query만이 아니라 **정답 선박 ID** 기준으로 수행한다. 랭커용 특징도 학습 내부 교차검증으로 생성한다.
- **선택 기준**: 내부 검증의 실제 Top-1 가중 정확도와 회귀 건수를 사용한다. NDCG만으로 채택하지 않는다. 한글 학습을 먼저 수행해 비한글 경로의 변화와 구분한다.
- **이유**: 이름이 강할 때와 톤수만 비슷할 때를 같은 고정 가중치로 처리하는 한계를 검증할 수 있다. 개선은 미측정이다.

### 2. DENSE-COVERAGE-01 — 상위 35개 밖의 Dense 특징도 제공

- **고정**: 검색 Top-35, 최종 후보 집합, 인코더, 학습·검증 행. 후보 확장 효과와 섞지 않는다.
- **변경**: 이미 계산한 전 카탈로그 내적에서 문자열·톤수 경로 후보의 cosine도 읽는다. 현재 Top-35 포함 여부를 별도 특징으로 유지한다. 순위와 z-score 정의를 고정하고, 후보 수를 바꾸면서 정규화 분포까지 바꾸지 않는다.
- **비교**: 기존 제한된 특징 대 전체 합집합의 Dense 특징을 동일 랭커 설정에서 비교한다. 양쪽 랭커는 동일 내부 학습 자료로 별도 fit하고, 외부 검증에서 재학습하지 않는다.
- **확장 순서**: 이 검증 후에만 tail 유사도·숫자·희소한 끝단 단어를 별도 특징으로 비교한다. 특정 오답 선박에 맞춘 예외 사전을 추가하지 않는다.
- **이유**: 유사도가 거의 같은 35위·36위 후보를 다르게 취급하는 효과를 분리한다. 전체 후보에 가산점을 주면 오답도 상승하므로 성능 개선을 가정하지 않는다.

### 3. LOOKUP-CONFLICT-01 — 충돌하는 조회 결과 재검토

- **고정**: 기존 검색기·점수식 또는 채택된 랭커 중 하나를 사전에 지정한다.
- **변경**: 호출부호/정규화 이름 조회 결과에 이름·숫자·메타정보 충돌이 있을 때, 바로 확정하는 대신 그 ID를 후보에 남기고 비교한다. 충돌이 없는 조회 경로는 같은 처리 조건을 유지한다.
- **학습 정보**: 조회별 중복 ID·관측 빈도·이름 변형 등 신뢰도 통계는 fit 선박에서만 만든다. 이름 충돌이 실제 개명일 수도 있으므로 불일치만으로 후보를 제거하지 않는다.
- **검증**: 조회 오류·검색 누락·후보 선택 오류를 분리한다. 그룹 보류는 새 선박 평가, 학습 선박의 보류 관측은 seen 보조 평가로 구분하며 합산하지 않는다.
- **이유**: 조기 반환이 놓친 오류는 재정렬을 개선해도 고칠 수 없다. 실제 서버 오류 비중은 아직 모른다.

### 4. EN-GLOBAL-RETRIEVAL-01 — 비한글 전역 문자 검색 추가

- **변경**: 공식 카탈로그 이름의 문자 2~4gram 인덱스 후보를 기존 후보와 합친다. 최초 소규모 후보 수(예: Top-20)는 내부 검증에서만 선택한다. 첫 글자·톤수 창에 의존하지 않는 검색 경로다.
- **고정**: 초기 비교에서는 AS-09 비한글 점수식을 그대로 적용해 검색 추가의 효과를 확인한다. 최초에는 모든 비한글 행에 고정된 추가 정책을 적용하여 별도 호출 게이트 튜닝을 섞지 않는다.
- **진단**: 첫 글자 오타, 단어 순서 변화, 숫자 표기, 톤수 결측/충돌 구간의 후보 포함률과 Fix/Break를 기록한다. 후보 수 증가만으로 개선을 주장하지 않는다.
- **지표**: n-gram 채널의 고정 Recall@K와 최종 가변 합집합 후보 포함률을 구분한다.

### 5. KO-EXAONE-UNION-01 — EXAONE의 추가 정답 회수 가능성 확인

- **진단 먼저**: 같은 공개 보류 입력에서 AS-09 구조의 후보에 없던 정답을 EXAONE 후보가 얼마나 추가하는지 확인한다. 결합 효과는 단독 정확도로 판단할 수 없다.
- **변경**: KO→EN 디코딩 결과를 영문 카탈로그 검색 채널에 넣고 후보 출처·생성 신뢰도·숫자 일치 등을 특징으로 제공한다. 기존 LFM map 전체 교체, 두 모델의 점수 단순 평균, 무조건 Top-1 덮어쓰기는 이 실험에 포함하지 않는다.
- **반영 조건**: 누락 정답 회수 이득이 있고 추가 후보가 만드는 Break·비용을 감당할 수 있을 때 다음 단계로 진행한다. 조건부 호출 게이트는 행 자체의 특징으로만 결정하고 내부 학습에서 고정한다.
- **기존 결과**: EXAONE 정방향 단독 가중 0.86540, 역방향 단독 0.82597은 공개 fold0 개발 점수다. AS-09 서버 0.92011과 직접 우열 비교하거나 결합 향상값으로 해석하지 않는다.

## 검증을 먼저 정합화해야 하는 이유

1. **AS-09 ZIP은 전수 학습 자산**이다. 그대로 공개 보류에 적용한 정확도를 OOF로 보고하지 않는다. 구조·설정을 기준으로 두되 인코더·조회·발음 생성기/사전·통계는 각 fit에서 만들고, 과거 학습 소스와 초기화 자산의 해시 차이부터 확인한다.
2. 기존 LFM map에는 생성 시점 모델 바인딩 이력 한계가 있다. 공유 map을 모든 fold에 재사용한 결과를 누수 없는 5-fold OOF로 부르지 않는다. 한글 map ON/OFF는 별도 조건으로 기록한다.
3. 첫 비교는 후보 ID 집합과 점수 구성요소를 저장해 확인한다. 후보 안에 정답이 없는 행을 평가에서 빼거나 검증 정답을 후보에 삽입하지 않는다. 랭커 학습에 양성이 없는 query를 제외하더라도 평가 분모에는 남긴다.
4. 배포된 G5-s42를 유지하고 fit-inner 선박 분할에서 특징·가중치·epoch·게이트를 선택한다. 외부 fold 결과를 본 뒤 같은 외부 fold에 맞춰 다시 조정하지 않는다. 공개 train 전체 EDA 이력이 있으므로 독립 최종 테스트라고 표현하지 않는다.
5. clean과 고정된 default/severe 변형, 톤수 결측·큰 오차, 숫자·접두사 충돌을 별도로 보고한다. 같은 선박의 여러 노이즈 변형을 독립 표본으로 합산하지 않는다. 모든 변형은 공식 공개 데이터만 사용한다.
6. 단계별 같은 행 비교 후 전체 5-fold OOF에서 한글/비한글/가중 점수·표본 수·Fix/Break·선박 단위 paired 95% CI를 확인한다. CI가 0을 포함하면 개선 확정으로 쓰지 않는다. 여러 후보 선택에 따른 편향도 명시한다.
7. 행 순서·부분집합·단독·반복 결과, 전체 로딩/인덱스/추론/저장 시간, 자산 크기를 확인한다. Windows Python 3.11.15와 목표 서버 3.11.17의 차이 및 실제 eval_kit 1.0/요청 1.1 차이는 별도 기록한다.

## 우선순위를 낮춘 변경

- **DPR03 전체 교체**: 기록된 동일 fold0 severe/map OFF 비교에서 DPR02 기준 0.98744064 → DPR03 전체 0.96108080, 차이 -2.6360%p, paired 95% CI [-4.709, -0.827]%p였다. 이는 해당 개발 조건의 결과이며 AS-09 서버 변화가 아니다. 초기화·학습률·학습 방식·점수식 여러 요소가 함께 바뀌었으므로 Stage A 단독 원인으로 해석하지 않는다.
- **Dense를 이름 점수로 무조건 직접 사용**: 같은 DPR03/K60에서 직결만 켜면 severe/map OFF 한글 정답 230→225였다. 후속 랭커의 조건부 특징으로 검증할 이유다.
- **발음 수 확대와 일률 자모 가중치 추가**: AS-06 기반의 이전 실험에서 일관된 개선을 보이지 않았다. AS-09에서도 효과가 없다고 확정하지는 않지만 첫 우선순위로 두지 않는다.
- **GPU 전환·미사용 tail 계산 제거**: 속도 개선 후보로 별도 검증한다. 속도 변화 자체를 정확도 향상으로 제시하지 않는다.
