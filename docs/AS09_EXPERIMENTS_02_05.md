# AS-09 개선 실험 2~5 준비 현황

2026-10-29 KST. 각 경로는 독립적인 **실험 코드**이며 AS-09 제출 entry point에는 연결하지 않았다. 실제 공개 보류 성능, 서버 성적, 비용 및 새 모델 채택은 미측정이다. 원본 ZIP을 만들거나 변경하지 않았다.

## 공통 비교 방법

동일한 선박 그룹 분할과 분할별 상위 자산을 사용한다. 입력 행은 `target_vessel_id`·fold를 제거한 뒤 후보를 생성하고, 정답은 예측이 완료된 이후에만 결합한다. 조회가 조기 반환한 행은 조회 경로로 따로 집계한다. 한글 여부는 경로명이 아니라 원래 이름의 `[가-힣]` 포함 여부로 판정한다.

`as09_candidate_extension.py`는 현재 `train_AS-09/script.py`의 `predict_rows`를 별도 함수로 만들어, 원래 후보 검색과 fallback이 끝난 뒤에만 추가 후보를 합친다. 기존 점수식과 동점 처리를 다시 구현하지 않는다. 생성 위치가 예상과 다르면 중단한다. 기존 검색 후보를 보존하는 경계 사례와 원본 함수 비교를 합성 데이터로 확인했다.

현재 `script.py`를 CRLF로 복원한 바이트의 SHA-256은 과거 로컬 AS-09 ZIP 내부 파일의 기록된 해시와 일치한다. 현재 `model.json`은 그대로 일치한다. 이는 과거 로컬 ZIP 검증 기록과의 대조이며, 서버에 업로드된 ZIP 바이트나 실제 실행 결과의 직접 확인은 아니다.

## 2. Dense 특징 범위

- `experimental_matchers/dense_coverage/comparison.py`: 동일한 후보·기존 점수·28개 특징 중, Dense Top-35 밖 후보의 `dense_sim` 결측만 전체 카탈로그 내적으로 채운다. 나머지 Dense 순위·z-score·margin은 기존대로 결측이다.
- `DenseCoverageTracer`는 검색기를 바꾸지 않고 후보를 추적한다. 현재 검색기에 전체 점수 반환 API가 없어 같은 행의 인코더를 한 번 더 호출하고, Top-35 점수가 기존 결과와 다르면 중단한다. 추가 추론 비용은 미측정이다.
- `train_ranker_pair`는 같은 학습 후보와 같은 랭커 설정으로 두 모델을 각각 학습한다. 정답이 후보에 없는 쿼리는 학습에서만 제외하고 검증에서는 유지해야 한다. `evaluate_ranker_pair`는 원래 이름으로 언어를 구분한다.
- 테스트: 합성 데이터 계약 4개와 기존 AS-09 인코더를 이용한 합성 40개 카탈로그 기능 확인. 실제 인코더는 전수 학습 자산이므로 성능 평가에 사용하지 않았다.

## 3. 조회 충돌 재검토

- `experimental_matchers/lookup_conflict.py`: 기존 조회가 반환할 ID의 숫자가 명확히 다르거나, 같은 영문 표기의 이름 유사도가 0.45 미만이면 조회 ID를 포함한 후보를 기존 점수식으로 다시 비교한다. 조회 ID를 제거하지 않는다.
- 0.45는 **사전 고정한 개발용 가설**이며 검증된 최적값이 아니다. 한글/영문 표기 차이만으로 충돌 처리하지 않는다. 국적·선종 불일치는 서로 다른 표기 체계일 수 있어 이 초기 경로의 호출 조건에서 제외했다.
- 충돌이 없거나 학습 조회가 꺼져 있으면 기존 경로를 그대로 사용한다. 통제 실험에서 조회 선박 오류, 후보 누락, 순위 오류를 따로 보고한다.

## 4. 비한글 전역 검색

- `experimental_matchers/en_global_retrieval.py`: 고정된 공식 카탈로그 이름만으로 문자 2~4-gram TF-IDF 색인을 만들고, 비한글 행별 상위 20개를 기존 후보에 합친다. 동점은 `vessel_id` 순이다.
- 학습 조회가 반환한 행은 그대로 우회한다. 순위는 기존 AS-09 점수식으로 정하므로 n-gram 검색 추가 효과만 비교한다. 고정 Top-K Recall과 기존 합집합 후보 포함률을 구분해야 한다.

## 5. EXAONE 후보 합집합

- `experimental_matchers/exaone_candidate_union.py`: 한글 입력 한 행을 KO→EN 디코더로 변환하고, 카탈로그 정확 일치 및 문자 유사 검색으로 후보를 모은다. 후보별 beam 순위·유사도·정확 일치 여부를 반환한다.
- 초기 실험은 기존 후보와 합친 뒤 기존 점수식으로 비교한다. 조회 조기 반환·비한글 행은 우회하고 디코더 입력 형식에 맞지 않는 한글 표기는 변환을 생략한다. 무조건 Top-1 덮어쓰기나 다른 테스트 행의 정보를 사용하지 않는다.
- 현재 작업공간에는 해당 fold의 EXAONE base/adapter 가중치가 없다. 테스트의 디코더는 합성 대역이며 EXAONE 모델 성능을 의미하지 않는다.

## 실제 평가를 위한 선행 조건

1. 팀이 배포한 **원본** `folds_group5_seed42.csv`가 필요하다. 임의 재생성하지 않는다. 평가기 1.0의 기준 SHA-256은 `9d09ede0f9254949aacf8cf80638a6c24de0ca5516ca3e9db329f55b9476ca51`이다.
2. 각 학습·보류 분할에서 만든 인코더, 카탈로그 임베딩, 조회표, 발음 변환표의 학습 ID·입력·가중치 해시를 확보해야 한다. 2번의 랭커 학습 특징은 내부 cross-fit도 필요하다. 기존 전수 AS-09 인코더나 생성 이력을 확인하지 못한 전수 map을 그대로 OOF에 사용하지 않는다.
3. `train_AS-09/model/full_encoder.pt`, `catalog_embeds_full_fp16.npy`와 기존 `KO-FUSION-01` 캐시는 현재 작업공간에 없다. 이 코드가 요구하는 Dense 자산이 없으면 조용히 다른 경로로 바꾸지 않고 중단한다.
4. 프로젝트의 `data/train.csv`는 팀 평가기의 원본 SHA-256과 일치하지 않는다. 이 작업공간의 별도 보관 원본은 평가기 해시와 일치한다. 실제 Windows 실행 시에는 각 PC에서 받은 원본 파일을 직접 확인한다.
5. 기존 `prepare_ko_fusion.py`는 분할별 조회·통계는 만들지만 기본 모델의 전체 한글 map을 복사하고 같은 경로의 인코더를 쓴다. 따라서 기존 `KO-FUSION-01`의 **분할 격리 여부는 추가 출처 감사가 필요하다**. 그 결과를 누수 없는 OOF로 확정하지 않는다.
6. 기존 `train_ko_fusion.py`, `evaluate_ko_fusion.py`는 `route == hangul_candidates`를 한글 판정에 사용한다. 한글 lookup 행이 있다면 비한글로 집계된다. 이전 Fold 0 숫자가 실제로 영향을 받았는지는 캐시가 없어 미확인이다. 새 비교는 원본 입력 이름으로 판정한다.
7. 현재 AS-09 소스의 한글 점수식은 유형/국적 전이표가 비어 있는 fallback에서 `meta_score`를 할당하지 않는다. 이 경우 예외 또는 이전 값 재사용이 가능하다. 새 실험은 해당 상황에서 중단한다. 현재 저장된 전수 `model.json`의 두 전이표는 비어 있지 않다. 기존 제출물에 오류가 발생했다고 단정하지 않는다.

검사: 서버 버전 가상환경에서 `python -m unittest tests.test_dense_coverage tests.test_as09_improvement_paths -v`. 테스트는 합성 예시이며, 성능 비교나 제출물 검사가 아니다.
