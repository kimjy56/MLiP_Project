# 역방향 언어모델 성능기록 검토와 활용 제안

기록 시각: 2026-10-25T10:27:33+09:00. 기존 기록·코드·공개 train/fold 식별자만 확인했다. 새 학습·언어모델 추론·전체 벤치마크·제출 ZIP 갱신은 수행하지 않았다. V1 검토는 `AUDIT-HCX-NC-01`, 추가된 V2 검토는 `AUDIT-HCX-NC-02`로 분리 보존한다.

## 판단

역방향 모델은 **노이즈가 있거나 비슷한 이름끼리 경합할 때 사용하는 이름 적합도 보조 점수**로 활용하는 것이 가장 유망하다. 기존 매칭기를 전면 교체하거나 V2가 제출 성능을 개선했다고 확정할 근거는 없다. V2의 합성 노이즈 오답 복구는 유용한 증거지만, 배포와 같은 조건에서 정답화와 오답화를 함께 측정한 성능은 아직 없다.

## 학습 완료 상태

- V1 `AS-HCX-NC-01`: 카탈로그 이름 → 관측 이름 조건부 언어모델. Fold 0 제외 9,850행에서 얻은 4,685개 이름쌍, 300 optimizer steps. 학습 루프 1,439.6초.
- V2 `AS-HCX-NC-02`: 같은 Fold 0 제외, 원본 4,685쌍 + 합성 2,129쌍 = 6,814쌍. 태스크 프리픽스와 노이즈 증강을 함께 변경했다. 300 steps, 학습 루프 1,725.9초. 두 변경의 개별 효과는 분리되지 않았다.
- 두 모델 모두 HyperCLOVA X 0.5B의 전체 24개 레이어 q/v LoRA. 학습 파라미터 1,966,080개. 학습 손실 감소를 최종 ID 정확도 개선으로 해석하지 않는다.
- 현재 `submit_AS-05.zip` 내부 manifest는 V1(`AS-HCX-NC-01`, prompt v1)이다. V2로 갱신하지 않았다.

## 원본 보류 기록에서 확인한 성능

V1 파일럿 128행은 한글/비한글 각 64행, 기존 검색기의 **고정 Top-35 후보 내 ID 선택**이다. 정답 선박의 학습 대상 ID 중복은 0건이다.

| 방식 | 한글 | 비한글 | 가중 정확도 | 기존 대비 정답화 / 오답화 |
|---|---:|---:|---:|---:|
| 기존 매칭기 | 64/64 | 64/64 | 100% | 기준 |
| V1 이름 평균 로그확률 단독 | 63/64 | 63/64 | 98.4375% | 0 / 2 |
| 기존 점수 + 0.20 × V1 평균 로그확률 | 64/64 | 64/64 | 100% | 0 / 0 |

이는 전체 카탈로그 검색 정확도나 서버 성적이 아니다. 기존 매칭기가 이미 전부 정답이므로 이 표본에서 추가 개선은 입증되지 않는다. 결합 계수 1.0에서는 한글 1행이 오답화된다. 0.20이 최적이거나 모든 입력에 안전하다는 근거도 없다. 현재 점수차 ≤1.0 게이트에 들어가는 행은 이 파일럿에서 1/128뿐이다.

V2 비교의 32행 파일럿은 위 128행의 부분집합이다. V1/V2 모두 한글 15/16, 비한글 14/16, 가중 91.875%이며 기존 진단에서는 이 32행 모두 정답이었다. 다만 이 비교는 **이름 언어모델 + 톤수·국적·선종·숫자 점수의 Factored 방식**으로, 순수 언어모델 단독 성능과는 다르다. 다른 표본의 99.958%와 직접 비교하지 않는다.

## V2 합성 노이즈 기록에서 확인한 기여

Fold 0 전체 2,372행에 합성 노이즈를 넣어 Baseline을 평가하고, 발생한 오답에 후보 8개 재정렬을 수행한 기록이다. 각 프리셋의 오답 선박과 V2 학습 대상 ID 중복은 0건이다.

| 합성 노이즈 조건 | 기존 오답 | V1 복구 | V2 복구 | 오답 중 정답이 Top-8에 없는 행 | 정답 표본 재검사 |
|---|---:|---:|---:|---:|---:|
| default | 5 | 1 | 1 | 3 | 128행, 오답화 0 |
| severe | 18 | 5 | 6 | 8 | 128행, 오답화 0 |
| name_only | 4 | 0 | 0 | 3 | 128행, 오답화 0 |

V2는 severe에서 `모닝 레나` → `Morning Lena`를 추가 복구했다. 기존 오답은 `Morning Carina`였고 정답-기존 오답 이름 점수 차가 V1 2.807에서 V2 4.528로 커졌다. `M/V HEMISPEHRE` 같은 철자 전위와 `SEASTAR VULAN` 같은 탈락 오타에도 후보 판별력이 관측된다.

### 보고된 전체 점수의 해석 제한

`experiments/benchmark_noise_full_fold0_v1_vs_v2.py`는 정답을 사용해 Baseline 오답 행을 골라 재정렬한다. 기존 정답은 프리셋마다 128행만 추가 검사한다. 최종 점수는 Baseline의 정오답 배열을 복사한 후 복구한 행만 True로 변경한다. 검사한 표본의 Break도 이 배열에서 차감하지 않는 구현이다(기록상 표본 Break는 0).

따라서 severe의 **96.680% → 97.308%(V1) → 97.601%(V2)**는 나머지 정답 행이 전부 유지된다고 가정한 값이다. severe에서는 기존 정답 2,226행이 재정렬 검사를 받지 않았다. V2-V1 차이 약 0.293%p는 한글 1행 추가 복구의 가중 기여다. 전체 배포 파이프라인 개선이나 부작용 제로를 증명하지 않는다.

또한 이 실험은 후보 Top-8을 모두 채점하며 AS-05의 점수차 게이트를 적용하지 않았다. AS-05는 점수차 ≤1.0, Top-35, 계수 0.20과 점수 상한에 의한 계산 생략을 사용한다. 따라서 실험의 복구 건수를 AS-05의 복구 건수로 옮겨 적지 않는다. 합성 노이즈의 발생률이 실제 비공개 입력 분포와 같다는 근거도 없다.

## 다른 성과 서술 정정

- V1의 과거 '4건 복구'는 학습 대상 선박이 포함된 두 후보 점수 비교였다. 최종 결합 재정렬의 정답화와 구분한다. 상세는 `AUDIT-HCX-NC-01`.
- V2 비교의 '12건 전부 정답' 중 **9건은 학습 대상 선박과 중복**된다. Fold 0의 나머지 3건도 기존 clean 진단에서 이미 정답이었다. 이 결과를 현재 Baseline 오답 12건 복구라고 부를 수 없다.
- 대표 6사례에서 정답 평균 로그확률 상승은 **5/6**, 정답-오답 점수 차 확대는 **4/6**이다. 6/6 모두 개선이라는 서술은 맞지 않는다. 평균 로그확률의 차이를 지수화한 배수를 문자열 전체 확률의 배수라고 해석하지 않는다.
- `FactoredNoisyChannelMatcher`에는 수동 결합 가중치, 톤수 정확 일치 보너스, 클리핑, 숫자 충돌 벌점 등이 있다. 언어모델과 통계·규칙을 결합한 모델이며 '규칙이 없는 순수 베이지안 모델'이라는 설명은 부정확하다.

## 활용 우선순위

1. **제출용 후보: 선택적 이름 재정렬.** 기존 검색과 메타정보 판단을 유지하며 낮은 점수차·필드 결측·이름과 메타정보의 충돌 등 입력에서 계산 가능한 조건으로 호출한다. V2는 오타·음역 노이즈 대응 후보로 비교한다. 정답 여부로 호출 대상을 고르지 않는다. 같은 카탈로그 이름의 여러 ID는 언어모델만으로 구분할 수 없다.
2. **고도화: 결합 방식을 학습.** 이름 점수·후보 간 차이, 기존 점수·차이, 톤수 오차, 국적/선종, 숫자 일치, 필드 결측을 작은 랭커에 입력한다. OOF로 만든 특징과 별도 보류를 사용해 이름을 믿을 때와 메타정보를 믿을 때를 학습한다. 가중치 조정이나 학습은 이번 검토에서 실행하지 않았다.
3. **후보 누락부터 분리.** severe 오답 18행 중 8행은 정답이 Top-8에 없었다. 이들은 재정렬만으로 복구할 수 없다. 오류가 의심되는 행에서 이름 검색 후보와 메타정보 검색 후보의 합집합을 확보하고 후보 수·시간을 함께 점검하는 방향을 제안한다.
4. **30분 제약.** 모든 행·모든 후보에 언어모델을 호출하지 않는다. V1의 기존 128행×35후보 채점은 약 28.4분이었다. AS-05의 과거 선택적 추론 시간 추정은 별도 소규모 표본/호출률 가정에 근거하며 V2의 서버 시간을 보장하지 않는다. 장기적으로 언어모델 점수를 작은 문자 기반 모델로 증류하는 방안은 비용 절감 가설로 남긴다.

## 다음 검증자에게 권하는 최소 작업

추가 대규모 학습보다 먼저, 학습에서 제외된 선박의 오답·모호한 정답·확실한 정답을 포함한 50~100행을 사용한다. AS-05와 같은 후보 구성·정답을 보지 않는 고정 게이트·결합식을 적용하고 Baseline/V1/V2의 Fix·Break·호출률·조건부 지연을 함께 보고한다. 정답은 선택 정책에 입력하지 않고 사후 평가에만 사용한다. 어려운 사례를 모은 표본 정확도를 전체 대회 점수로 해석하지 않는다. 동일 표본에서 여러 계수를 선택하고 최종 일반화 성능으로 발표하지 않는다.
