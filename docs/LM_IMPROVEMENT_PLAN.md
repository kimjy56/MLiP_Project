# 언어모델 성능 향상 계획

계획 ID: `PLAN-LM-AR06-01` · 2026-10-25 KST. 기존 소스·학습 기록·원 논문을 검토한 제안이다. 구현·학습·새 모델 추론·제출 ZIP 생성은 실행하지 않았다. 아래 설정과 효과는 실험 전 가설이다.

## 우선 판단

현재 HyperCLOVA X 0.5B에서 우선 바꿀 것은 **후보 구별을 직접 학습하는 목표**, **학습쌍의 커버리지와 한글 음역 다양성**, **OOF 기반 점수 결합**이다. 정방향은 이름 후보 생성, 역방향은 후보 내 이름 적합도 채점에 활용하는 역할 분리를 권한다. 더 큰 모델이나 LoRA 용량 확대는 이 변경들의 효과를 확인한 뒤 비교한다.

역방향 이름 모델은 동일한 카탈로그 이름의 서로 다른 선박 ID에 동일한 점수를 준다. 이 경우 톤수·국적·선종·안전한 호출부호 정보가 필요하다. 후보에 없는 정답도 역방향 재정렬만으로 복구할 수 없다.

## 1. 가장 유망한 모델 변경: 혼동 후보를 활용한 순위 학습

현재 목표는 정답 카탈로그 이름에서 실제 관측 이름을 잘 생성하는 것이다. 최종 의사결정은 정답 이름과 비슷한 다른 이름 사이의 순위를 고르는 문제다. 정답 생성 NLL을 유지하면서 이 순위를 직접 학습하는 항을 추가한다.

관측 이름 x, 카탈로그 이름 c에 대한 점수를 다음과 같이 둔다.

```text
s(x, c) = 관측 이름 토큰과 EOS의 평균 log P(x | c, task)
L_rank = -log softmax([s(x,c+)/tau, s(x,c1-)/tau, s(x,c2-)/tau])[positive]
L_total = L_SFT + beta * L_rank
```

- 정답 1개 + 혼동 오답 2개부터 시작한다. beta=0.1, tau=1은 초기 비교값이며 최적값이 아니다. pairwise softplus(s_negative - s_positive)도 대안이지만 첫 실험에서 두 손실을 동시에 탐색하지 않는다.
- 오답은 해당 학습 fold에서 학습한 검색기·매칭기가 실제로 높게 평가한 후보, 이름의 일부·번호만 다른 후보, 골격이 비슷한 후보에서 고른다. 쉬운 무작위 오답만 사용하지 않는다.
- **동일 정규화 카탈로그 이름의 다른 ID를 이름 모델의 오답으로 넣지 않는다.** 이름 점수로 구별할 수 없으므로 이름 단위로 묶는다. 가상의 잘못된 선박 DB나 외부 별칭을 추가하지 않는다.
- 마이닝·사전·증강은 fit fold 안에서만 수행한다. 검증 정답으로 후보를 보충하거나 어려운 행을 학습에 넣지 않는다. 검증에서는 정답이 빠진 행도 그대로 평가한다.
- 정답+오답 2개면 학습 채점 쌍이 늘어난다. optimizer step 수가 같아도 계산량이 같지 않으므로 총 후보쌍 수·토큰 수·시간을 함께 보고한다.

RankT5는 Transformer를 pairwise/listwise 순위 손실로 학습하는 근거이고, BRIO는 생성 확률과 후보 품질의 정렬을 학습하는 관련 연구다. 두 논문의 과제는 이 선박 문제와 다르며, 위 역방향 점수에 대한 적용은 본 프로젝트의 제안이다. 논문의 개선 폭을 우리 성능으로 전용하지 않는다.

## 2. 데이터 커버리지와 행 단위 손실

현재 코드는 언어별 확률 0.7/0.3을 두고 각 언어에서 복원 추출한다. 이미 한글을 많이 뽑는 설계이므로 단순한 한글 비율 확대는 우선순위가 낮다.

먼저 언어 혼합 0.7/0.3과 2,400 draw를 고정한 채 각 언어 내부를 **셔플 후 소진까지 비복원 순환**하는 방식을 비교한다. 뽑힌 고유쌍 수, 원본/증강 비율, 이름당 반복 횟수, 토큰 수를 남긴다. 이 변경만으로 비한글 자료 전체를 보게 되는 것은 아니다.

그 다음 같은 샘플 인덱스를 사용해 token-mean CE와 **각 관측 이름의 평균 토큰 NLL을 먼저 계산하고 행별로 평균한 CE**를 비교한다. 현재의 token-mean은 한 microbatch에서 긴 이름에 더 많은 비중을 준다. 행 단위 평균은 현재 역방향 평균 logp 채점과 손실 단위를 맞추는 가설이다. 이미 언어별 샘플링을 70:30으로 한 상태에서 손실에도 70:30을 중복 적용하지 않는다.

커버리지 진단 이후에만 300/600/1200 step처럼 학습량을 비교한다. 외부 보류 fold가 아닌 fit 내부 검증의 후보 순위 지표로 checkpoint를 고르고, 추가 step에서 한글 과적합·비한글 변화·새 이름 일반화를 함께 확인한다. 최종 G5 점수로 매 checkpoint를 반복 선택하지 않는다.

## 3. 한글 음역 증강을 실제 학습 대응에서 확장

V2의 한글 증강은 62쌍이며 주로 공백과 제한된 모음 변형이다. 다음은 fit 데이터 안의 동일 target에 대한 관측 별칭과 한글–영문 정렬에서 얻은 음역 변형을 확장한다.

- 같은 영문 부분에 대응하는 복수의 한글 음역을 fit에서 수집한다. 자음·모음·장음·중국 병음 표기의 변이를 기존 실제 대응이 뒷받침하는 범위에서 사용한다.
- 원본쌍과 증강쌍의 추출 비율을 따로 제어한다. 증강 개수만 늘려 정상 대응을 희석하지 않는다.
- 숫자·서수·식별 접미사는 보존한다. 다른 공식 선박 이름에 해당하는 변형, 식별 단어가 사라지는 변형은 제외하거나 별도 모호 사례로 분류한다. 동명 선박 ID는 이름 증강으로 구별할 수 없다.
- 합성 검증은 clean 및 이름만 변형한 검증과 분리한다. 학습과 검증이 같은 변형 규칙을 공유하면 그 규칙에 대한 적응을 일반적 test 강건성으로 확대하지 않는다.

이번 계획은 추가 외부 학습 데이터나 외부 번역 API를 사용하지 않는다. 현재 태스크 프리픽스 KO_TRANSLITERATION/EN_TYPO_RECOVERY는 이미 있으므로 새 개선으로 다시 세지 않는다. 학습 시 톤수·국적을 이름 채널에 바로 섞는 변경은 이름 판별력 실험과 분리한다.

## 4. 정방향 HCX의 카탈로그 제한 생성

`name_decoder/hyperclova.py`는 자유 생성 뒤 ratio 근사 검색을 한다. 공식 카탈로그 이름의 토큰 prefix trie로 디코딩을 제한하는 방식을 비교할 수 있다. 카탈로그에 실제로 존재하는 이름만 생성하므로 철자 오류 때문에 근사 검색에서 다른 선박으로 이동하는 문제를 줄일 가능성이 있다. 정답 이름을 선택한다는 보장은 없다.

- 카탈로그 전체로 고정 trie를 구성하고 greedy와 beam 4 정도를 먼저 비교한다. 이름별 모든 ID를 보존하고 최종 ID는 별도 제원 판단에 넘긴다.
- **기존 ByT5 경로에는 이미 ByteNameTrie와 제한 beam search가 구현되어 있다.** ByteNameTrie는 ByT5 바이트 토큰 전용이므로 HCX 토크나이저에 그대로 재사용하지 않는다. prompt/continuation 경계, 대소문자·공백·EOS를 맞춘 별도 토큰 trie가 필요하다.
- 현재 생성→근사 검색 Top-10과, 새 제한 생성의 이름 Top-K를 다른 지표로 구분한다. beam을 늘린 결과는 같은 비용의 성능과 함께 비교한다.
- 정방향 후보는 기존 검색 후보에 합친다. 기존 후보를 제거하는 전면 교체는 별도 실험이다. 생성 K, 합집합 후보 수, 압축 후 정답 포함을 구분한다.

GENRE의 카탈로그/엔티티 이름 제한 생성이 방법론적 근거다. ByT5는 문자·음운·노이즈를 다루는 대안이지만 현재 모델보다 우월하다고 확인된 것은 아니다. 새로운 대형 모델 도입보다 기존 HCX와 이미 구현된 ByT5 경로의 입력 표현을 같은 조건에서 비교하는 데 의미가 있다.

## 5. 언어모델 점수를 최종 ID 정확도로 연결

현재 AS-05는 기존 점수 + 0.20 × 역방향 평균 logp와 점수차 게이트를 사용한다. 이 계수나 게이트가 최적이라는 근거는 없다. 이름 모델이 나아져도 원래 점수가 과도하게 우세하거나 정답이 shortlist 밖이면 바뀌지 않는다.

OOF로 만든 기존 점수·마진, LM 점수·마진, 이름 유사도, 숫자 충돌, GT/IGT 오차, 국적·선종 호환, 결측을 작은 결합 랭커에 입력하거나 언어별 계수를 보정한다. 후보별 학습 예측을 그대로 메타학습에 넣지 않고 교차 적합한다. LM이 fit에서 보지 않은 행의 점수를 사용하며, 최종 외부 fold는 LM과 랭커 모두의 학습·계수 선택에서 제외한다. 필요 시 외부 fit 내부의 추가 분할로 구현한다.

같은 관측 이름을 모든 후보에서 채점하므로 관측 토큰 수 T는 후보 간 같다. 역방향 sum logp를 mean logp로 바꾸는 것만으로 그 행의 **LM 단독 순위는 달라지지 않는다**. 결합 계수의 행별 스케일은 달라질 수 있으므로 이를 별도의 성능 향상으로 혼동하지 않는다.

게이트는 정답 여부를 보지 않고 입력·기존 점수만으로 결정한다. 바뀐 이름 점수/결합 함수가 현재 점수 상한 기반 계산 생략의 전제를 유지하는지도 검증한다. 양수 보너스나 새 랭커를 넣으면 기존 pruning을 그대로 쓸 수 없다.

## 권장 실행 순서와 평가

| 단계 | 변경 | 비교 조건 | 보고할 것 |
|---|---|---|---|
| 0 | 기존 V1/V2의 실제 AS-05 게이트 진단 | 동일 기존 자산·후보·결합식 | 호출 대상 전체의 Fix/Break, 호출률, 시간. 정답으로 실행 대상을 고르지 않음 |
| 1 | 언어 내부 비복원 순환 | draw 수·0.7/0.3·CE·모델 고정 | 고유쌍/반복/노출 토큰과 clean/노이즈 순위 |
| 2 | 행 평균 CE | 동일 draw 목록·학습량 | 이름 길이별 결과, 언어별 순위 |
| 3 | 혼동 오답 순위 손실 | 정방향·검색·메타 고정 | 후보 내 Top-1/MRR, 분리 마진, 최종 ID Fix/Break, 추가 학습 비용 |
| 4 | 한글 음역 증강 확대 | 위 선택 구성과 원본 노출량 기록 | 음역 유형별 변화, clean 손실 여부 |
| 5 | HCX 제한 생성 또는 OOF 결합 | 각각 별도 실험 ID | 이름 후보 포함률 / 최종 ID 정확도와 비용 |

작은 진단은 실험 코드와 실패 유형을 확인하는 용도다. 어려운 행을 모은 표본의 점수를 전체 성능으로 외삽하지 않는다. G5는 퇴보 검사이며 개발 중 본 공개 train을 독립 최종 테스트라고 부르지 않는다. 후보 포함률, 정답이 후보에 있을 때의 조건부 정확도, 전체 정확도, seen/unseen, 한글/비한글을 구분하고 최종 점수는 0.7×한글+0.3×비한글로 계산한다. clean과 합성 노이즈는 별도 보고한다.

일차 목표는 **같은 후보에서 LM의 순위 판별력이 좋아지는가**, 다음은 **제출과 같은 게이트에서 추가 Fix가 Break를 넘어서는가**다. 손실 감소나 특정 두 후보 점수 차 상승만으로 최종 개선이라고 판단하지 않는다. step 수·LoRA rank·학습률·증강·후보 수를 한꺼번에 바꾸지 않는다.

후속 실행은 지정 `.venv-server`에서 한다. 현재 Windows에 해당 환경이 없으므로 모델 실행은 이번 범위에 포함하지 않았다. 학습 CPU 스레드/발열 제한을 유지하고, GPU·실제 서버에서 속도를 별도 확인한다. 추론 비용은 로딩·검색·LM 채점·저장을 구분하며 전체 제한은 기존 평가 기준을 따른다.
