# 여러 컴퓨터에서 작업하기

코드·규칙·집계 보고서는 팀 내부 비공개 Git 저장소로 동기화한다. 원본 데이터·OOF·fold·가상환경·가중치·제출 ZIP은 제외한다. CSV라는 이유만으로 모든 파일을 제외하지 않으며, 기존 분석 집계 CSV는 유지한다.

## 새 Windows 컴퓨터

1. 팀 저장소를 clone한다. 기존 작업 컴퓨터의 변경 사항이 commit·push돼 있어야 받을 수 있다.
2. 프로젝트 폴더에서 [Windows 환경 설치](../environment/README.md)의 PowerShell 명령을 실행한다.
3. 대회 원본 CSV는 각 PC에서 공식 경로로 직접 받아 `data/` 같은 로컬 폴더에 둔다. 파일을 AI 채팅이나 Git에 업로드하지 않는다.
4. 고정 fold·평가기·필요한 OOF/모델은 팀 승인 공간에서 받는다. fold를 새로 생성하지 않는다. 파일 해시·실험 ID·환경을 대조한다.
5. 기본 데이터 위치는 프로젝트 루트의 `data/`다. 공식 CSV를 `data/train.csv`, `data/vessel_catalog.csv`로 배치한다. 다른 위치는 `--data-dir` 옵션으로 지정한다.

환경 설치에는 데이터가 필요하지 않다. 시스템 Python이나 다른 PC의 가상환경을 복사하지 않는다. OS가 다른 컴퓨터에는 해당 OS의 wheel을 설치한다. macOS는 이 Windows/CUDA 설치 파일의 지원 대상이 아니다.

## 컴퓨터를 바꿀 때

- 시작: `git status` → 로컬 수정 사항 정리 → `git pull --ff-only`.
- 종료: 코드·문서를 명시적으로 선택해 stage → `git diff --cached --stat`와 실제 diff 검토 → 요청된 범위에서 commit·push.
- 동시 작업: 서로 다른 브랜치를 쓰고 병합한다. 데이터·모델은 각 PC에 보존하고 내부 공유 시 해시로 확인한다.
- ZIP은 요청할 때만 생성한다. Git 동기화를 위해 ZIP을 다시 만들지 않는다.

## 이미 추적된 파일 확인과 제외

```text
git ls-files -ci --exclude-standard
```

출력이 있으면 현재 추적 중이면서 `.gitignore` 규칙에도 해당하는 파일이다. 실제 제외 대상인지 확인한 후 **정확한 파일 경로에만** 다음을 적용한다.

```text
git rm --cached -- "실제 제외 대상 경로"
```

이 명령은 현재 PC 파일은 남기고 Git 인덱스에서만 제외한다. 전체 저장소에 `git rm -r --cached .`를 실행할 필요는 없다. 제거 변경을 commit·push해야 원격의 최신 상태에도 반영된다. 다른 PC가 그 삭제 커밋을 pull하면 기존 추적 파일이 로컬에서도 제거될 수 있으므로 해당 PC의 필요한 데이터·산출물은 먼저 저장소 밖에 백업한다.

이전 커밋의 파일까지 지우지는 않는다. 기록 재작성·강제 push는 별도 작업이며 이번 요청에서 수행하지 않는다.

`.gitignore`는 Git 추적 방지일 뿐 AI 도구의 읽기나 클라우드 전송을 차단하지 않는다. 원본은 공식 사이트에서 각 PC로 받는 방식을 유지한다.

## 이번 작업공간 점검

현재 추적 파일 및 로컬에서 접근 가능한 Git 이력을 확인했다. 원본 CSV·OOF·fold·가상환경·가중치·ZIP에 해당하는 추적 항목은 없어서 실제 `git rm --cached` 대상은 없었다. 기존 CSV는 집계 분석표다. `.gitignore`를 확장해 다른 위치의 데이터 파일·OOF·모델 확장자·가상환경·행 단위 오류 파일을 추가로 제외했다.

이 확인은 현재 로컬 저장소 범위이며, 확인하지 않은 원격 브랜치·다른 PC·외부 복제본의 상태까지 보장하지 않는다. 이번 작업에서 commit·push나 과거 이력 재작성은 하지 않았다.
