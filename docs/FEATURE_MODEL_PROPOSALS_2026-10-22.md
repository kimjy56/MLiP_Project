# 현재 JY 구현을 기준으로 한 특징·모델 설계 제안

작성: 2026-10-22 KST. 상태: **planned / 설계만 작성**. 신규 데이터 분석 실행·학습·성능 비교·모델 변경·ZIP 생성·대회 제출은 하지 않았다. 아래 효과는 가설이며 Public 예상 점수나 예상 개선 행 수를 제시하지 않는다.

## 판단 기준과 현재 구현

- 목적: 항만 입력 한 행과 공식 카탈로그를 비교하여 같은 선박 ID 하나를 선택한다. 학습 정답에 없는 카탈로그 선박도 선택할 수 있는 입력–후보 쌍 점수 구조를 유지한다.
- 공식 지표: 한글 정확도 0.7 + 비한글 정확도 0.3. 한글은 입력 이름에 `[가-힣]` 포함 여부로 결정한다.
- 제공 규모: train 12,222행, 카탈로그 78,595척. 팀 집계는 정답 5,851척, 한글 1,191행/382척, 선박당 1~4행이다. 이 문서에서는 집계를 새로 계산하지 않았다.
- 팀 사실기록 §5·§7: train과 카탈로그의 선박 규모·선종 분포 차이, 한글의 여러 음역 방식, 이름 오타와 다른 필드 잡음의 동반 현상이 보고됐다. 추가 평가 분포나 실제 데이터 생성 원인은 미확인이다.
- 최신 완료 기록은 `project_log/experiments/JY-10-OOF.json`: G5 가중 0.9956138494, 한글 1,184/1,191, 비한글 11,021/11,031. 로컬 개발 검증이며 Public 예측값이 아니다. 이미 검증 오류를 참고해 규칙을 수정해 온 선택 편향도 있다.
- 이미 구현/실험한 항목: 32개 특징, 단어별 IDF·최소/끝 단어 유사도·숫자 충돌·잔여 발음, 총톤수/국제총톤수 각각의 차이, 한글 단어/약어 확장, CatBoost·MLP 튜닝·앙상블, 비한글 독립 잡음 증강. 이를 신규 도입으로 제안하지 않는다.
- 실제 확인한 차이: `prepare_row`는 원본 한글 정규화값을 보존하지만 roman/phonetic/단어 view에는 확장한 이름을 넣는다. **확장하지 않은 원래 음역의 비교 점수**는 별도 입력으로 남지 않는다.
- `tokens_score`는 양방향 토큰별 최대 유사도를 이용한다. 각 토큰에 일대일 대응이나 순서 보존을 강제하지 않는다. 기존 전체 이름·끝 단어 특징에 순서 정보가 전혀 없다는 뜻은 아니다.
- 국적·선종 표는 학습 데이터의 선박별 중복을 제거한 대응 빈도를 정규화한다. 표본 수·분포 불확실성·미등록 상태를 출력 특징에 별도로 보존하지 않으며 없는 대응에는 0이 들어간다. `arrival_year`는 현재 `QUERY_COLUMNS`에 없다.
- 현재 CatBoost 목적함수는 Logloss, MLP는 후보 쌍별 BCE다. 언어별 가중치는 이미 있다. 같은 입력의 후보 수에 비례해 그 입력의 총 손실 기여가 달라질 수 있다.

## 특징 제안 — 각각 독립 비교

### F1. 확장 전후 음역과 변환 근거를 함께 입력 — 우선

의문: 한글을 한 가지 영문 표기로 확정하면서 유용한 원래 음역이 사라지는가? 근거: 사실기록 §7의 혼합 음역 방식, 현재 `prepare_row` 구현.

- 한글만 변경하고 비한글 경로는 기존 모델을 사용한다.
- 기존 확장 음역 점수를 유지하고 확장하지 않은 음역의 전체/토큰 유사도를 추가한다.
- 변환된 토큰 비율, 미변환 한글 비율, 약어·숫자·단어사전 변환 여부, 확장 전후 유사도의 차이를 추가한다. 이것들은 변환 근거를 나타내는 값이며 정답 확률이 아니다.
- 실제로 복수 표기를 지원하는 규칙에 한해서 상위 변환들의 후보 일치 점수와 차이를 분리한다. 처음에는 변환 수를 무작정 늘리지 않고 원래 음역 경로 복원부터 시험한다. 여러 경로의 최댓값만 취하면 과한 변환이 유리해질 수 있어 원래 점수·변환 종류를 함께 남긴다.
- 학습 데이터에서 변환 비용/빈도를 추정한다면 학습 fold 안에서만 추정한다. 선박 전체 이름→정답 ID의 사전으로 만들지 않는다.
- 성공 해석: 변환이 많이 일어난 행의 오답 선택이 줄고 기존 정상 변환 사례 손실이 작으면 변환 불확실성 표현의 유용성을 뒷받침한다. 이는 추가 평가 분포를 입증하지 않는다.
- 비용: 전처리·이름 비교 추가, 기존 카탈로그 정규화 자산 재사용 가능. 구현·추론 시간은 미측정. 현재 제출 0회.

### F2. 순서를 보존하는 단어 대응 특징 — 우선

의문: 공통 선사명/반복 단어가 토큰별 최대 유사도를 부풀리는가? 근거: 사실기록 §7의 순서 보존 관찰, 현재 양방향 최대 매칭.

- 한글만 변경. 후보 검색, 기존 점수와 비한글 모델을 고정한다.
- 동적 계획법으로 왼쪽부터 순서를 보존하며 단어를 대응시킨다. 한 단어를 여러 후보 단어에 중복 사용하는 것을 제한한다. 공백 분리/결합 경로는 별도 실험으로 둔다.
- 새 특징: 정렬 전체 점수, 대응된 단어의 최소 유사도, 대응하지 못한 단어의 IDF 질량, 숫자가 붙은 단어 위치의 일치/충돌.
- 기존 숫자열 일치·끝 단어·잔여 발음 특징과 중복되지 않도록 추가 효과를 비교한다. 정렬 점수 자체로 후보를 하드 제외하지 않는다.
- O-06은 후보 확대·톤수 점수·단어 경로를 함께 바꾼 기록이므로 그 하락을 모든 단어 정렬의 실패로 해석하지 않는다. 여기서는 순서 보존 특징 하나만 추가한다.
- 성공 해석: 제원이 같은 유사 이름 후보 간 선택 오류가 줄면 채택 근거가 된다. 숫자/약어 포함 사례와 토큰 수 불일치 사례의 악화도 분리한다.
- 비용: 토큰 수에 따른 DP 추가. 카탈로그 토큰은 사전 계산하고 후보 안에서만 수행한다. 시간 미측정, 현재 제출 0회.

### F3. 국적·선종 대응의 근거와 불확실성 구분

의문: 대응표에 자료가 없어서 0인 경우와 충분한 자료에서 불일치인 경우를 혼동하는가? 근거: 사실기록 §5·§7의 미관측 선종과 연도별 국적 불일치 보고, `make_assets`·`features` 구현.

- F3a: 한글의 국적만 먼저 변경하고 선종은 고정한다. 원래 대응 점수, 대응표에 기여한 고유 선박 수, 입력 국적 미등록, 후보 국적 미관측, 국적 결측, 대응 분포의 엔트로피를 별도 특징으로 준다. 최소 특징값 0.5로 의미를 덮어쓰지 않는다.
- 자기 선박의 정답으로 만든 통계가 그 선박의 학습 특징을 지나치게 확신시키지 않도록 학습 쪽도 선박 단위 내부 OOF 또는 leave-one-vessel-out 통계를 사용한다. 외부 검증 fold에는 외부 학습 fold 전체에서 만든 표를 적용한다.
- F3b: F3a를 고정한 다음 `arrival_year`와 연도별 대응 근거를 추가한다. 연도별 표본이 적으면 전체 대응으로 수축하는 계수를 내부 검증에서 고른다. 기준 연도는 학습 시 고정하고 시스템 현재 시각이나 테스트 최대 연도를 사용하지 않는다.
- F3c: 선종에도 알려진 대응/미관측/표본 수를 적용한다. 큰 선종 분류를 쓰려면 공식 데이터에서 학습 가능한 근거를 먼저 확보한다. 외부 해운 분류표를 가져오거나 미관측 세부 선종을 인기 선종으로 강제하지 않는다.
- 기존 AR 계열의 연도별 수동 감점과 달리, JY 쌍 모델에 **대응의 증거량·미등록 여부**를 제공하는 실험이다. 연도만 추가하는 아이디어 전체가 팀 최초라는 뜻은 아니다.
- 성공 해석: 미등록·소표본 사례에서 기존 정답이 유지되고 잘못된 국적 보정이 줄면 근거가 된다. 연도 관찰만으로 실제 국적 변경이라는 원인을 확정하지 않는다.
- 비용: 자산 크기·조회 연산 증가, 내부 통계 생성 비용. 시간 미측정, 현재 제출 0회.

### F4. 톤수 오차 방향과 두 입력값의 일관성 — 후순위

의문: 절댓값 오차만으로는 입력 제원 간 모순을 구별하기 어려운가? 근거: 총톤수·국제총톤수가 다른 행이 있다는 팀 집계와 현재 절댓값 상대 오차 특징.

- 기존 `gross_gap`, `international_gap`, `best_gap`을 유지한다.
- 유효한 양수에 한해 `log(gross/catalog_gt)`, `log(international/catalog_gt)`, `log(gross/international)` 및 두 입력이 후보보다 같은 방향/반대 방향인지 추가한다. 결측은 별도 마스크로 처리한다.
- 현재 이미 두 톤수의 개별 차이를 쓰므로 이 제안의 새 요소는 **부호와 입력 사이 관계**다. 특정 3~5% 구간에 가산점을 주거나 ±X% 밖을 삭제하지 않는다.
- 한글/비한글 중 한 경로에서 먼저 독립 비교한다. 추론 입력과 카탈로그 톤수만 사용한다.
- 성공 해석: 두 톤수가 다른 사례에서 선택이 개선되는지, 동일 톤수 사례에서 불필요한 변화가 생기는지 확인한다. 기존 특징과 정보가 중복되어 이득이 없을 수도 있다.
- 비용: 후보별 상수 시간 연산 추가. 실제 시간 미측정, 현재 제출 0회.

## 모델 설계

### M1. 한 입력의 후보를 함께 학습하는 랭커 — 모델 우선순위 1

현재 각 후보의 정답 여부를 따로 학습하는 BCE/Logloss를 **입력 한 행에서 정답 후보를 1등으로 만드는 손실**과 비교한다. 과거 U04에 랭킹 비교 계획은 있었으나 현재 JY 코드에는 구현되지 않았다.

첫 시험은 MLP의 입력 32개·망 크기·학습 후보를 그대로 고정하고 학습 단위/손실만 바꾼다. 입력 q의 후보 집합 C(q)에 대해:

`loss(q) = -score(q, gold) + logsumexp(score(q, c), c in C(q))`

- 최종 합산은 후보 쌍 수가 아닌 입력 행 단위로 한다. 양쪽 언어를 함께 학습할 때는 `0.7 * mean(loss_hangul) + 0.3 * mean(loss_non_hangul)`를 사용한다. 기존에도 언어 가중치는 있었으며 새 요소는 **행 단위 경쟁과 정규화**다.
- 후보 자리가 서로 다른 선박 ID여도 같은 점수망을 재사용한다. 고정 선박 ID별 출력층이나 ID 인기도 특징은 넣지 않는다.
- 증강 복사본 수로 원본 행의 총 가중치가 자동 증가하지 않게 원본/복사본 손실을 먼저 묶는다. 복사본 가중치는 내부 검증에서 고정한다.
- 한글 경로를 먼저 교체해 비한글 모델의 예측은 고정한다. MLP 단독 BCE와 단독 랭킹을 비교한 후 채택된 변경을 앙상블에 넣는 시험을 따로 한다.
- CatBoost는 동일 후보·특징으로 PairLogit을 대안 비교할 수 있다. 이 손실은 object weight 대신 pair weight를 사용하므로 한 입력의 쌍 가중치 합과 언어별 총 가중치를 명시해야 한다. 단순히 기존 `sample_weight`를 복사하지 않는다.
- 후보 그룹은 **서로 다른 테스트 행의 그룹이 아니라 입력 한 행과 공식 카탈로그에서 얻은 후보 집합**이다. 행별 독립 조건과 양립한다.
- 추론에는 기존 점수망과 argmax를 사용하므로 손실 변경 자체가 후보 수나 망 연산량을 늘리지는 않는다. 실제 속도·점수 개선은 미측정이다.
- 근거: [PyTorch 2.7 CrossEntropyLoss](https://docs.pytorch.org/docs/2.7/generated/torch.nn.CrossEntropyLoss.html), [CatBoost ranking losses와 pair weights](https://catboost.ai/docs/en/concepts/loss-functions-ranking).

### M2. 이름·제원·메타정보를 분리해서 점수를 합치는 모델

현재 MLP는 모든 특징을 함께 받아 `톤수 결측이면 이름 불일치일 것이다`와 같은 학습 데이터 특유의 상호작용을 배울 수 있다. 비한글 독립 잡음은 이미 적용했으므로 이를 신규 증강으로 다시 제안하지 않는다. 이번 가설은 구조적으로 상호작용을 제한하는 것이다.

`score = name_branch(name_features) + tonnage_branch(tonnage_features) + metadata_branch(type_flag_evidence, year)`

- 각 분기는 작은 학습 모델이며 이름 분기는 톤수/국적 결측 정보를 받지 않는다. 국적·선종 분기는 F3의 근거가 준비된 뒤 사용하거나 현재 특징으로 구조 효과부터 비교한다.
- 먼저 현재 MLP와 비슷한 전체 파라미터 예산, 같은 BCE 목적함수로 분리 구조만 비교한다. M1의 손실 교체와 동시에 바꾸지 않는다.
- 비한글 경로에서 먼저 비교하면 잡음 동반 관찰과 직접 연결된다. 한글 적용은 별도 시험이다.
- 학습에 없는 선박을 후보에서 선택할 수 있으며 분기별 기여를 개발 데이터에서 분석할 수 있다. 점수 합은 보정 확률이 아니다.
- 단점: 실제로 필요한 이름–톤수 상호작용까지 잃을 수 있다. 원본 G5와 잡음 조합별 시험을 함께 통과해야 한다.

### M3. 실제로 혼동한 후보에 집중하는 학습 — 후속

현재 어려운 오답은 이름/발음 유사도와 톤수의 고정 수식으로 고른다. 이후에는 외부 학습 fold 안에서 만든 내부 OOF 모델이 높게 평가한 오답 후보를 수집한다. 특히 톤수·국적·선종이 같거나 비슷하고 이름 일부만 다른 후보를 활용한다.

일반 오답도 일정 부분 유지하며, 후보 수·특징·모델을 고정해 음성 선택 방법만 비교한다. 외부 검증 정답을 보고 선택하거나 실제 test 예측을 채굴하지 않는다. 기존의 어려운 오답 선택 자체가 없었다는 제안이 아니라 **선택 기준을 모델 오류로 바꾸는 제안**이다. 비용은 내부 OOF 학습 추가로 상대적으로 크며 미측정이다.

## 비교 순서와 해석

1. 현재 코드/자산/후보/앙상블 실제 설정을 고정하고 기준을 재현할 준비를 한다. 기록의 0.6:0.4와 로더의 0.5:0.5, soft-meta 분기 같은 확인된 불일치를 새 특징 효과와 섞지 않는다. 수정을 택하면 먼저 별도 기준판으로 기록한다.
2. **F1 → F2 → M1**을 우선 비교한다. 최초 비교는 각각 동일 기준에서 단독으로 수행하고, 효과를 확인한 뒤 결합한다.
3. F3a → F3b/선종 별도 비교. F4와 M2는 그 뒤, M3는 비용을 고려한 후속이다.
4. 후보 검색은 우선 고정한다. 각 실험에서 검색 합집합 포함률, 후보 압축 후 포함률, 후보에 정답이 있을 때 선택 정확도를 분리한다. 이미 후보가 없어서 틀린 행은 새 랭커로 해결했다고 주장하지 않는다. 검증 후보에 정답을 삽입하지 않는다.
5. G5는 퇴보 검사. 한글/비한글, 선박별, 학습에서 본/새 선박, 약어·숫자·다중 단어·미등록 선종·두 톤수 불일치 등으로 집계한다. 같은 보류 예측의 개선/악화 수와 선박 단위 불확실성을 기록한다. 현재 G5처럼 새 선박만 있는 검증에서는 seen 지표를 미측정으로 둔다.
6. 독립적으로 설계한 표기/결측 스트레스 시험은 가정별 민감도 점검으로만 쓴다. 원래 오류 분포를 모르므로 MIX 점수로 Public을 예측하지 않는다. 한글의 순서 무작위 변경·과한 증강은 기본 학습에 추가하지 않는다.
7. 표·정규화·튜닝은 외부 학습 fold 안에서만 fit한다. 보조 그룹 분할에서도 방향을 확인하되 과거에 전혀 보지 않은 최종 시험이라고 부르지 않는다.
8. 팀 기준의 한글 1%p 초과 퇴보 제한을 적용한다. 통과 자체로 제출을 추천하지 않는다. 실제 제출은 팀 배정과 별도 요청을 따른다. 현재 설계 비용은 제출 0회, 구현·추론 시간은 미측정이다.

## 규칙 및 운영 범위

모든 제안은 입력 한 행, 공식 카탈로그, 공식 train에서 미리 fit한 고정 자산을 사용한다. 테스트 전체/다른 행 통계·투표·순위·배치 통계는 사용하지 않는다. 동일 행을 단독/부분/순서 변경으로 실행해 같은 결과인지 검사한다. 카탈로그 ID 순서를 포함해 동점 처리를 고정한다. 외부 선박 DB·변환표·번역 API·추론 중 인터넷 호출은 추가하지 않는다. 현재 큰 사전학습 모델이나 대규모 카탈로그 합성 학습을 필수 단계로 두지 않는다.

카탈로그의 `size/unit/deadweight_tonnage`만으로 후보 인기도를 학습하는 방향은 이번 우선안에 포함하지 않는다. 쿼리에 직접 대응하는 필드가 없어 train의 선박 종류 선호를 다시 학습할 위험이 있으며, 총톤수와 재화중량은 같은 물리량으로 간주할 수 없다.

서버 제약은 사용자 제공 규칙 기준 Python 3.11.17, 6 vCPU/RAM 26GB/L4, 추론 30분, ZIP 10GB/해제 32GB다. 실제 서버 버전 호환과 로딩·검색·특징·점수·저장을 포함한 비용을 측정한다. 기존 10진수 Public 예상 점수는 이 제안의 근거로 사용하지 않는다.
