# 선박명 처리 개선안

상태: **초기 계획 보존; 일부 구현·검증 완료**. 기록일: 2026-10-18 KST.
이 문서의 아래 본문은 실행 전 제안이다. 이후 E004/E005에서 다중 표현·토큰/숫자·가중 발음·발음 키 검색을 비교했고, E007/E008에서 TF-IDF n-gram 검색과 네 검색 경로의 모든 조합을 구현·비교했다. 최신 결과는 [검색 조합 결과](RETRIEVAL_COMBINATIONS.md)를 따른다. G2P·임베딩·학습형 음역 대응은 아직 구현하지 않았다.

## 1. 해결할 문제와 근거

- 현재 RapidFuzz ratio는 앞부분 차이를 별도로 크게 벌점화하지 않는다. 실제 한계는 문자 삽입·삭제 차이가 발음의 유사성을 충분히 반영하지 못한다는 점이다.
- 단순 로마자화와 모음 제거는 일부 변형을 연결하지만 정보 손실과 충돌을 만든다. 순수 문자 검색을 폐기하기보다 여러 표현을 함께 보존한다.
- 기존 선박 그룹 보류의 한글 정답 후보 포함률은 99.51%, 최종 정확도는 92.68%였다. 오답 16행은 검색 누락 2행·선택 오류 14행이다. 따라서 검색 확장과 후보 구분 특징 개선을 따로 평가해야 한다.
- 학습의 한글 기록은 1,191행·382척으로 작다. 복잡한 음역·임베딩 학습이 반드시 개선된다고 가정하지 않는다.

## 2. 1단계: 원본과 구분 정보를 보존하는 다중 표현

각 이름에서 원본, NFKC 대소문자 정규화본, 토큰 보존본, 공백 제거본, 로마자본, 숫자열을 별도로 만든다. 기존 자음 위주 발음 키도 보조 표현으로 유지하며 유일한 표현으로 사용하지 않는다.

- 숫자와 호수를 보존한다. NO. 7 / 제7호 등의 처리는 원래 형태와 정규화 가설을 함께 둔다.
- 선박을 구분할 수 있는 접미어·접두어를 일괄 삭제하지 않는다.
- 영어 한 글자씩 읽는 이니셜과 한글 음역은 공식 학습 쌍에서 확인된 대응을 우선 사용한다.
- 한국어의 붙여쓰기, 영어의 띄어쓰기·하이픈 차이를 위해 토큰 비교와 붙인 이름 비교를 병행한다.

검증하려는 효과: 공백·구두점 변형을 줄이면서 숫자·단어의 구분 정보를 잃지 않는지 확인.

## 3. 2단계: 문자열 특징을 더 정밀하게 구성

### 3.1 문자 n-gram TF-IDF 검색

카탈로그 이름과 로마자 이름의 2–4글자 조각을 벡터화해 유사도를 계산한다. 예를 들어 일부 글자가 바뀌어도 나머지 조각으로 후보를 찾는 보조 경로가 된다. 같은 문자 공간이 전제이므로 한영 문제를 TF-IDF만으로 해결하지는 못한다.

IDF는 공식 카탈로그와 허용된 학습 폴드 자산에서만 계산해 고정한다. 테스트 이름을 모아 fit하거나 테스트 빈도를 사용하지 않는다.

### 3.2 발음 대응을 반영한 가중 편집 거리

모든 치환을 동일하게 벌점화하는 대신 비슷한 소리로 대응할 수 있는 문자·문자열 변환은 비용을 낮추는 가설을 검토한다. PH↔F처럼 여러 글자와 한 글자의 대응도 다룰 수 있는 정렬이 필요하다.

초기에는 일반적인 소수 규칙을 독립 특징으로 만들고, 공식 학습 이름 쌍에서 확인한 문자열 대응을 추가하는 방식을 비교한다. 복수 변환을 허용하되 후보 수를 제한한다. 어떤 치환도 모든 이름에서 정답이라고 가정하지 않는다. 특히 B/V, R/L 등의 무조건 통합은 오답 선박을 비슷하게 만들 수 있다.

문자열·음역의 정렬 및 대응 비용 학습은 작은 데이터에서 불안정할 수 있다. 최소 관측 수·규제·미관측 변환의 기본 비용을 두며, 학습 선박을 제외한 검증에서 이득을 확인한다. 외부 선박 이름·정답 사전을 추가하지 않는다.

### 3.3 공통 접두어와 구별되는 단어의 유사도 분리

전체 이름 점수, 토큰별 점수, 공통 부분을 제외한 잔여 이름 점수를 따로 만든다. 카탈로그에서 자주 나오는 단어는 IDF로 가중치를 낮추는 특징을 검토하되, 해당 단어 자체를 삭제하지 않는다.

예: Morning Composer와 Morning Cello의 공통 Morning만으로 높은 점수를 받지 않도록 Composer/Cello 차이를 별도 특징으로 전달한다. 이는 기존 오류를 설명하는 가설이며 이 변경의 효과를 측정한 것은 아니다. 관찰한 검증 사례의 정답 이름을 수동 별칭 사전에 추가하지 않는다.

## 4. 3단계: 학습한 이름 표현으로 확장 — 선택 실험

### 4.1 공식 학습 쌍에서 부분 이름 대응 학습

한글 입력 이름과 정답 영문 카탈로그 이름에서 반복적으로 나타나는 부분 이름·이니셜 대응을 학습 폴드만으로 수집한다. 토큰 수가 같다는 이유만으로 반드시 같은 단어라고 단정하지 않고, 정렬의 확실성과 반복 관측 여부를 확인한다. 확인되지 않은 부분은 기본 문자열 검색으로 처리한다.

전체 이름을 외우는 사전과 부분 이름의 일반화 효과를 분리해 기록한다. 선박 그룹 보류 정답과 전체 train에서 만든 사전을 섞지 않는다.

### 4.2 다국어 임베딩 검색

공개 범용 사전학습 가중치를 이용해 한글·영문 이름을 벡터화하고 코사인 유사도로 검색하는 경로를 추가한다. 설명서의 paraphrase-multilingual-MiniLM-L12-v2는 검토 가능한 후보이며, 이 문서 작성 중 다운로드·평가하지 않았다.

일반 문장 임베딩은 의미가 비슷한 이름과 동일 선박을 혼동할 수 있으므로 단독 판정 기준으로 쓰지 않는다. 필요하면 공식 train 정답 이름 쌍으로 대조 학습하고, 같은 접두어·비슷한 숫자·유사한 제원의 다른 선박을 어려운 음성으로 사용한다. 같은 선박의 여러 이름을 서로 음성으로 취급하지 않도록 ID를 확인한다.

학습 데이터의 규모가 작아 과적합 가능성이 있다. 추가 조정 없이 사용하는 인코더, 공식 쌍으로 조정한 인코더를 별도로 비교한다. 외부 선박 데이터셋은 사용하지 않는다. 추론용 가중치·토크나이저는 동봉하고 오프라인으로 실행한다.

## 5. 후보 통합과 최종 비교

원본 문자 검색, 로마자/발음 검색, 선택적 임베딩 검색, 기존 톤수 검색에서 얻은 후보를 합친다. 점수 척도가 서로 다르므로 단순 점수 합산을 기본값으로 두지 않는다. 경로별 후보 할당 또는 순위 기반 결합을 비교한다.

검색 단계에서는 같은 최종 후보 예산(예: 100개; 미검증 실험 설정)으로 재현율과 시간을 비교한다. 후보 수가 가변인 실험은 후보 수 평균·상위 분위수와 가변 후보 포함률을 함께 기록한다. 정답을 검증 후보에 강제로 넣지 않는다.

최종 MLP나 트리 모델에는 전체 이름 유사도, 로마자 유사도, 가중 발음 거리, 잔여 단어 유사도, 숫자 일치·충돌, 선택적 임베딩 유사도를 각각 전달한다. 톤수·선종·국적 특징도 유지한다. 고정된 임의 비율로 이 모든 증거를 하나의 점수로 미리 축약하지 않는다.

## 6. 실험 설계

| 계획 ID | 변경 | 고정 조건 | 확인할 지표 |
|---|---|---|---|
| P03-A | 토큰·숫자·원본을 보존한 표현 | 그룹 분할·검색 예산·나머지 설정 | 한글/비한글 후보 포함률, 숫자·동명 오류 |
| P03-B | n-gram 검색 + 가중 발음 비교 | 동일 분할; 각 경로를 따로 추가 | 후보 예산별 재현율, 최종 Top-1, 시간 |
| P03-C | 잔여 단어·숫자·음역 비교 특징 | 후보 목록과 분류기 설정 고정 | 선택 오류 감소, 가중 정확도 |
| P03-D | 다국어 임베딩 경로 | 동일 분할·최종 후보 예산 | 추가로 회수한 정답, 잘못 추가한 유사 후보, 시간·용량 |
| P03-E | 공식 이름 쌍으로 부분 대응/임베딩 조정 | 학습 폴드만 사용; 미조정 버전 비교 | 새 선박 일반화, 과적합·희귀 표기 성능 |

기존 수치와 새 실험이 같은 분할인지 확인한다. 새로운 검증 예측을 보고 반복 조정한 경우 모델 선택용 결과로 명시한다. 전체 OOF 가중 정확도, 한글 표본 수, 선박별 변동, 검색/선택 오류 분리, 전체 실행 비용을 기록한다.

## 7. 권장 적용 순서

먼저 P03-A와 P03-C로 정보 보존과 후보 구분을 개선한다. 다음으로 P03-B를 통해 음역·문자 검색 경로를 보강한다. 여전히 검색 누락 또는 이름 표현 문제가 남고 비용 대비 이득이 확인될 때 P03-D/E를 진행한다.

초기 계획 작성 시점에는 코드·모델·submit.zip을 교체하지 않았다. 이후 진행 결과는 위에 연결한 E004/E005와 전체 학습·패키징 E006 기록을 확인한다.
