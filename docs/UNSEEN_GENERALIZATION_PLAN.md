# 새 선박 일반화 모델 설계안

상태: planned, 2026-10-21 KST. 사용자 제공 조교 팁과 현재 코드 검토에 따른 설계이며 신규 학습/검증 실행 결과가 아니다.

## 근거와 전제

- 조교의 약 9만/5천/8만5천 척, 학습 정확도 1.0이면 제출 약 0.8이라는 설명은 근사·추측이다. 저장소 기준 카탈로그 78,595행, 학습 정답 5,851척, 학습 행 12,222개를 사용한다. 실제 테스트의 unseen 비율은 미확인이다.
- 현재 JY-01은 RapidFuzz S/P/T 검색, 30후보 압축, 32개 비교 특징, LightGBM 이진 후보 분류, 학습 호출부호/별칭 조회다. 기존 AS/OPT OOF와 최종 JY-01 구성은 동일하다고 가정하지 않는다.
- 입력별 후보 점수 구조는 카탈로그의 학습 미등장 ID도 출력할 수 있다. 핵심은 미등장 이름·오류 패턴으로의 일반화다.
- 30분은 전체 실행 상한, 10,000행은 계획용 추정이며 실제 평가 행 수가 아니다.

## 권장 구조

다중 표현 검색(원문/문자 n-gram/발음/제원) → 서로 보완되는 후보 합집합 → 입력-후보 비교 특징과 랭커 → 고정 ID 동점 규칙. 호출부호 조회는 이름·제원 충돌을 검사하는 별도 비교안으로 둔다. 검증 사전은 학습 fold에만 fit한다.

## 증강 원칙

- 학습 fold의 실제 기록과 정답 카탈로그 이름을 맞춰 띄어쓰기·기호·접미 표현, 영문 철자 누락/치환, 한글 음역 변이, 제원 결측/반올림·관측 오차 분포를 추정한다. 원본 학습 쿼리와 카탈로그 이름 모두 증강의 출발점이 될 수 있다.
- 이름 숫자는 선박 식별에 중요하므로 임의 교체하지 않는다. 후보가 다른 실제 선박을 명확히 가리키도록 바뀌거나 정보가 과도하게 사라진 합성 행은 제거 또는 낮은 가중치로 다룬다.
- 각 변형을 먼저 단독 비교하고 조합한다. 한글 음역은 규칙/학습 fold 쌍으로 만들며 온라인 번역·외부 선박 DB를 쓰지 않는다. 그럴듯한 음역이어도 실제 관측 분포와 다를 수 있으므로 실제 보류에서 검증한다.
- 실제 행을 유지하고 합성 행의 총 가중치를 제한한다. 선박별 합성 개수·총 가중치 상한으로 특정 선박 반복을 억제한다. 언어 가중은 0.7/0.3 평가 목적을 고려하되 합성 행 수가 언어 비율을 왜곡하지 않도록 분리한다.
- hard negative는 이름이 비슷하지만 번호가 다른 선박, 톤수가 비슷하지만 이름이 다른 선박, 발음이 유사한 다른 ID에서 뽑는다. 채굴 모델·오류 패턴은 학습 fold 안에서만 얻는다.

## 카탈로그 합성과 unseen 검증

공식 전체 카탈로그를 검색 인덱스로 사용하는 것과 그 항목에서 라벨이 붙은 합성 학습 쿼리를 만드는 것을 구분한다. 주 그룹 OOF에서 외부 검증 fold 선박 ID를 합성 지도학습에도 넣으면 순수 unseen 선박 시험의 의미가 바뀐다. 엄격한 비교에서는 그 ID들을 합성 학습에서 제외하되 후보 카탈로그에는 계속 유지한다. train에 전혀 등장하지 않는 카탈로그 ID는 학습 fold에서 추정한 변형기로 합성하는 별도 조건으로 둔다. 전체 카탈로그 합성은 이 차이를 명시한 별도 실험으로 관리한다. 최종 학습 확대는 공식 허용 데이터 범위 내에서 검증 후 결정한다.

## 표현·랭커

- 한 행의 후보 집합을 query group으로 둔 LambdaRank를 기존 이진 분류와 비교한다. 추론에서 정답 삽입 금지; 학습 쌍의 정답 보충은 기존 규칙을 명시해 비교 조건으로 고정한다.
- 기존 숫자 인덱스 기반 어려운 후보 추출 로직과 특징 삭제 후 컬럼 대응을 실행 전에 감사한다. 현재 발견만으로 성능 저하 원인이라고 단정하지 않는다.
- 학습형 표현은 일반 의미 유사도보다 철자·발음·숫자 구별을 평가한다. ByT5 계열은 후보 연구 대상이며 이 데이터에서 우수하다고 확인한 것은 아니다. 원문+발음+숫자/톤수 특징을 유지한다.
- 선형 probe는 새 ID를 출력하지 못하는 학습 ID 다중분류보다 입력-후보 쌍의 일치 판별로 설계한다. t-SNE/UMAP은 보조 진단으로만 사용하고 성능 근거는 Recall@K(실제 고정 K), 후보 포함률, Top-1으로 삼는다.

## 평가와 채택

배포 그룹 5-fold 및 공식 평가기로 실제 보류를 평가한다. 한글/비한글, 조회 사용/미사용, 기존/새 선박(적합한 별도 행 분할에서 구분), 검색 누락/압축 탈락/랭커 오류를 나눈다. 후보 수가 가변인 합집합 포함률을 Recall@K로 부르지 않는다. 깨끗한 실제 보류와 사전에 고정한 변형 시험은 각각 보고한다. 학습에서 등장하지 않은 오류 조합 시험도 보조로 둔다. 외부 보류로 early stopping·증강 확률을 조절하지 않는다. 후보 비교 후 선박 부트스트랩 CI와 보조 그룹 seed로 재확인하고 반복 선택 편향을 밝힌다. 전체 공개 train은 과거 EDA/최종 학습에 쓰였으므로 독립 최종 테스트라고 표현하지 않는다.

공식 제출 0.7835113288의 원인을 unseen 하나로 단정하지 않는다. 같은 구성 재현, 런타임 설정/모델 자산 일치, 누수 검사와 후보 단계 진단이 먼저다. 신규 실험은 각 실행 전에 별도 JSON ID로 설정을 고정한다. 이 문서는 설계 요청에 대한 planned 항목이며 학습 또는 ZIP 생성을 승인한 것으로 확대하지 않는다.
