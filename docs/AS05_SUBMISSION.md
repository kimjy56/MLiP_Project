## 사용한 모델과 연결 방식

기존 `submit_AS-04.zip`의 규칙 매칭기와 저장된 `model/model.json`을 그대로 기반으로 사용한다. 완성된 **역방향 `AS-HCX-NC-01`** 병합 가중치와 토크나이저를 함께 넣었다. 정방향 LoRA 실험인 **AS-HCX-05와 제출 ID AS-05는 다르다**. 재학습·양자화·가중치 변환은 하지 않았다.

기존 후보 1·2위 점수 차가 1.0 이하인 모호한 행만 상위 35개 후보에서 재선택한다. 식은 `baseline_score + 0.20 * mean_log_probability`이며 관측 이름과 EOS의 평균 로그확률을 사용한다. 같은 카탈로그 이름의 ID를 유지한다. 후보의 원래 점수가 현재 최고 결합 점수보다 작으면, 로그확률이 0 이하라는 상한으로 이후 계산을 생략한다. 이 생략은 게이트 안의 top-35 승자 선택 결과를 보존한다.

점수 차 1.0 게이트는 이번 제출 연결에서 추가한 계산량 제한이다. 기존 128행 파일럿을 AS-05 전체 성능으로 재표기하지 않는다. 입력 행 순서·다른 행·남은 실행 시간으로 게이트나 점수를 바꾸지 않는다. 이름 길이/특수 토큰 등 학습 토크나이저 계약을 벗어난 행은 기존 매칭기 결과를 사용한다.

CPU 스레드는 4로 제한한다. CUDA를 사용할 수 있으면 원본 float32 가중치를 GPU로 이동하며 TF32는 사용하지 않는다. GPU가 없는 현재 PC에서는 CPU 경로를 확인했다. 인터넷이나 서버의 train.csv는 필요 없다. 서버의 `data/test.csv`, `data/vessel_catalog.csv`를 읽고 `output/submission.csv`만 저장한다. 실행 로그에는 집계 건수만 출력한다.

## 이번 점검 범위

- 공통 검사기 `check_submission.py --n 12 --single 1`: 실패 0, 경고 1. ZIP 구조·요구 패키지·출력 형식 정상. 순서 변경 0/12, 절반 0/6, 단독 0건 차이.
- 실제 역방향 가중치 로딩 및 카탈로그 2후보 fixture: 평균 로그확률 결합과 전수 계산의 승자 일치, 후보 순서 변경 일치. **소프트웨어 기능 검사이며 보류 성능 수치가 아니다.**
- 새 ZIP 안 코드의 Python 구문 검사, 훈련 manifest 대비 가중치/토크나이저 해시 확인.
- 미확인: 서버 Linux/Python 3.11.17/CUDA 경로, 전체 입력 처리 시간, AS-05 전체 정확도, 독립적인 5-fold OOF.

공통 검사기는 소규모 CPU 실행 시간에서 긴 실행 시간을 외삽하여 경고 1건을 냈다. 측정된 전체 서버 실행 시간이 아니며, 검사기 안내의 1,200초는 현재 프로젝트 문서의 30분 안내보다 오래된 값이다. 서버 시간 충족을 보장하지 않는다. 전체 시간 확인이 필요한 다음 담당자는 실제 처리 행 수·게이트 진입 수·계산 후보 수와 시간을 함께 기록한다.

현재 역방향 가중치는 Fold 0 제외 학습 모델이다. 이를 Fold 1~4 오류에 적용한 결과는 학습에 등장한 선박을 포함할 수 있으므로 OOF 성능 향상 근거로 사용하지 않는다.

## 소규모 표본 실행 시간 추정 (2026-10-24 KST)

사용자 요청에 따라 30,000행 전체 실행을 중단하고 **대표 300행 + 이름 점수 8쌍 + 모호한 후보 5행**만 측정했다. 전체 실행 완료 결과는 없다. 현재 ZIP을 수정하지 않았다.

- CPU 4스레드, 300행 전체 약 12.07초. 이 표본은 역방향 호출 0행이라 별도로 모델 비용을 측정했다.
- 기존 매칭 처리: 행당 23.77ms. 모델 냉시작(공용 모듈 import 포함) 10.74초.
- 모호한 5행: 역방향 추가 평균 0.787초/행, 최대 0.892초/행. 실제 채점 후보 평균 1.8개, 최대 2개. top-35를 모두 계산하지 않고 상한으로 대부분 생략했다.
- 추정식: `고정 시간 + 행 수 × 기본 매칭 시간 + 행 수 × 재정렬 비율 × 재정렬 추가 시간`.
- 아래는 **재정렬 비율 1% 가정**이다. 보수 추정은 모호한 행의 측정 최대시간을 쓰고 전체에 50% 여유를 더했다.

| 행 수 시나리오 | 표본 기반 예상 | 보수 추정 |
|---:|---:|---:|
| 8,200 | 4.6분 | 7.1분 |
| 10,000 | 5.5분 | 8.6분 |
| 30,000 | 16.1분 | 24.9분 |

행 수는 가정이며 실제 비공개 평가 규모를 뜻하지 않는다. 표본·후보 분포와 하드웨어가 달라지면 추정이 달라진다. 재정렬 호출 비율 또는 후보 계산량이 많으면 30분을 넘을 수 있어 서버 상한 보장으로 표현하지 않는다. GPU 가속 이득은 추정에 반영하지 않았다. 근거: `reports/as05_runtime_estimate.json`, `project_log/experiments/AS-05-RUNTIME-02.json`.
